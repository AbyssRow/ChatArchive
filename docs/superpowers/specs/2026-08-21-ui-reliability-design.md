# ChatArchive UI 全面收口设计

日期：2026-08-21  
状态：已批准

## 目标

在不修改 SQLite schema、导入原文和 `E:\ChatArchive` 真实档案的前提下，修复时间线方向、跨页日期、附件信息展示及审查中确认的 UI 高影响缺陷，并补齐原 WinUI 重写设计已经定义但尚未接入的搜索筛选。

## 时间线与附件

- `ConversationRepository.ListMessages` 的公开契约保持不变：每次查询最新或更旧的一页，返回页内按 `(timestamp_ms, id)` 升序排列的消息。
- 首次载入最新 80 条后把列表定位到底部；滚到顶部阈值时加载更旧页并插入集合头部。`ItemsStackPanel.ItemsUpdatingScrollMode=KeepItemsInView` 保持首个可见项，加载时视口不跳。
- 每次切换会话或搜索跳转都生成新的请求版本；旧请求即使迟到也不得更新当前 UI。
- 日期分隔按系统本地日期生成且跨分页边界只出现一次；消息行只显示 `HH:mm:ss`。
- 搜索跳转设置正确的当前会话 ID、旧消息游标和焦点消息；上下文载入后把焦点滚入视野。
- 附件先投影为展示模型：可用图片显示全部缩略图，可用文件/音视频显示通用打开入口，缺失项显示缺失提示与可取得的文件名。
- 正文若只是 `[图片]`、`[文件]`、声明路径、源路径或文件名等技术信息则隐藏，真实文字说明保留。媒体类型消息没有附件记录时按缺失媒体处理。
- 收到与发出的消息使用相同附件规则；系统消息使用居中灰色模板。

## 搜索与其余交互

- 搜索 UI 接入 `SearchFilter` 已有的全部字段：平台、会话类型、具体会话、发送者、消息类型、本地日期起止。
- 搜索状态公开 `HasMore`；末页隐藏/禁用加载按钮，禁止空游标重复从第一页加载。新查询或筛选变化使旧请求失效。
- 会话筛选空标签解析为无筛选，不再访问不存在的第二段。
- 联系人会话使用单击跳转；图片另存为使用带点扩展名；非图片附件用系统默认应用打开。
- 查询、附件操作和保存失败通过窗口级 `InfoBar` 显示，不再静默吞掉。
- 导入对话框关闭后解除临时事件订阅；导入期间禁用重复入口。

## 测试与安全

- 新增不启动窗口的 App 逻辑测试，覆盖时间线页合并/日期边界、附件投影、筛选解析、搜索末页和最新请求规则。
- 扩充 Core 测试，覆盖会话、消息类型和本地日期区间组合筛选。
- 终验运行 Release x64 构建、全量测试、格式校验和依赖漏洞检查。
- UI 冒烟使用临时数据或真实库副本；不得直接以 `E:\ChatArchive\chat_archive.db` 作为验证写入目标。

## 明确不变

- 不修改 schema_version 1、仓储分页公开签名、导入去重规则或真实聊天内容。
- 不拆分 `MainWindow` 为新页面体系；本轮在现有 Core/App 分层内提取少量纯逻辑并加固状态边界。
